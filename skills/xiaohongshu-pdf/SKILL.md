# PDF 转小红书发布包

当用户要求 PDF 转小红书图片、分页或发布文案时使用。一次交付图片**和**文案，不要等用户再次索要。用户明确要求去除可见水印时才处理；不把猜测当事实，不声称已发布。

## 工作流程

1. 找到指定源文件，核对名称及所在目录；Windows 路径不一定能直接访问。如在 Google Drive，先查找并核对父文件夹，再下载原文件。不得改动原 PDF。
2. 查看总页数、尺寸、是否可提取文字。图片型 PDF 要逐页视觉阅读（可分批生成缩略图），忠实理解内容；不可依赖单页推断整篇，不清楚的内容要标注而非编造。
3. 检查**每一页**的水印位置及周围文字。位置或大小不同就分开处理；水印覆盖正文时不可盲目修复或声称正文完整，应保留可读内容并告知用户。Gemini/NotebookLM 可见标识通常在右下角，但不同文件并不保证坐标相同。不要使用固定矩形无差别处理整份文件。
4. 为每次任务在源 PDF 附近创建全新的、不会覆盖的文件夹，若存在则追加 `-2`、`-3`；图片按 `01.jpg` 等排序。脚本支持 4:3 画布，尽量保留整页，避免裁掉底部注释。按视觉检查后的页码和矩形坐标填写配置（比例坐标，基于原页宽高）。无水印页面不填。用 `render.py` 生成图片，然后逐页核对：顺序、清晰度、文字完整性、水印是否有残留、修复是否明显。必要时调整配置重新生成到新目录。若图片文字过小，说明局限或另行优化排版，不要伪称已经优化。
5. 基于整个 PDF 内容写简体中文发布文案：包含吸引人的标题、适合平台的正文、自然的互动结尾和相关话题标签。提炼重点并忠于原意，不杜撰数据、来源或医疗效果。关系及心理内容避免诊断和保证效果，尊重自主与安全。文案应可直接复制发布。保存在同一个文件夹的 `发布文案.txt`，并在回复中提供全文或明确链接。20 张以上图片应提示平台单篇张数限制可能变化，按实际上传界面拆分，不要声称一定可一次发表。
6. 如果目标位于 Google Drive，先在原文件的父目录新建唯一文件夹，再上传全部图片及文案，并检查文件数量、名称。不要仅生成沙箱文件而声称已同步。若上传失败，明确说明并提供可用本地结果。默认不自动发布小红书。
7. 最终答复提供文件夹链接、图片数量、文案位置、去水印方式及未能处理的问题。

## 脚本使用

依赖 Python 3、PyMuPDF、Pillow；需要修复时还需 `opencv-python-headless` 和 `numpy`。本脚本负责**图片处理**，文案由执行该 Skill 的 AI 在读完整份材料后生成；脚本本身不调用模型，也不上传云端。

```bash
python -m pip install PyMuPDF Pillow opencv-python-headless numpy
python skills/xiaohongshu-pdf/render.py source.pdf --output-parent /path/to/parent --name 小红书发布包 --watermarks boxes.json
```

`boxes.json` 示例（每页从 1 开始，坐标为 0 到 1 之间的 `[左, 上, 右, 下]`，仅为示例，必须先核对实际页面）：

```json
{"1": [[0.92, 0.965, 1.0, 1.0]], "2": [[0.91, 0.96, 1.0, 1.0]]}
```

不需要去水印时省略 `--watermarks`。处理采用局部图像修复，会改变水印区域的像素；须逐页检查，不保证图案无痕。输出路径一旦存在会自动另建目录，永不覆盖源文件或先前结果。可把文字型 PDF 文本导出用于阅读，但图片型 PDF 须视觉阅读。
